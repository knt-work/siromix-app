# Branch change specs

Use one Markdown file per independently reviewable change. Match its filename to the branch slug. For example, `codex/refactor-camera-lifecycle` uses `refactor-camera-lifecycle.md`.

Record the goal, scope, relevant current feature specs, required behavior, implementation decisions when necessary, and verifiable acceptance criteria. Add the verification results when complete. Keep the spec with the change when it merges. Update the current feature spec only when the product behavior it describes changes.
